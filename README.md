# 콘서트 알리미

좋아하는 가수의 공연 일정이나 공식 채널의 공연 소식이 새로 뜨면 이메일, 문자, 휴대폰 푸시로 알려주고, 전체 일정을 웹페이지로 보여줍니다.
웹페이지에서 "예매할게요"를 고르면 예매 오픈 일시를 공식 발표에서 알아서 찾아, 오픈 하루 전과 10분 전에 다시 알려줘요.
GitHub Actions가 자동으로 확인하므로 서버나 켜둔 컴퓨터가 필요 없고, 모두 무료로 쓸 수 있어요(문자만 건당 요금).

지금 추적하는 아티스트: Coldplay, Oasis, 혁오, 실리카겔, Green Day

## 어떻게 동작하나요

1. 매시간 GitHub Actions가 `watch.py`를 실행해요.
2. **공식 채널(매시간):** 각 아티스트의 공식 인스타그램 새 게시물 중 공연·투어·티켓 관련 단어가 들어간 글, 그리고 공식 웹사이트에 새로 생긴 줄 중 날짜나 공연 관련 단어가 들어간 줄을 찾아요.
3. **공연 일정 API(3시간마다):** 국내 공연은 KOPIS(공연예술통합전산망) 공식 API, 해외 공연은 Ticketmaster 공식 API에서 아티스트 이름으로 찾아요.
4. 이전에 본 적 없는 공연이나 소식이 있으면 켜둔 채널로 알림을 보내요. 같은 내용은 다시 알리지 않아요.
5. 결과를 `data/state.json`에 저장하고, `docs/index.html` 웹페이지를 다시 만들어요.
6. 알림의 "예매할지 고르기" 링크를 누르면 웹페이지의 그 공연으로 가요. "예매할게요"를 누르고 예매 오픈 일시를 저장하면 `data/picks.json`에 기록되고, 그 즉시 리마인더가 준비돼요.

처음 확인할 때는 이미 있는 게시물과 사이트 내용을 기준으로 저장만 해요. 아티스트를 처음 추가하면 그때 이미 잡혀 있는 공연은 알림 없이 웹페이지에만 올라가고, 그 뒤로 새로 뜨는 공연부터 알려줘요. 처음부터 다 받고 싶으면 `config.yaml`에서 `on_first_run: true`로 바꾸세요.

## 설정하기 (약 20분)

### 1. 저장소 만들기
GitHub에서 새 저장소를 **공개(Public)** 로 만들고 이 폴더의 파일을 모두 올리세요. 무료 계정에서 웹페이지(GitHub Pages)를 쓰려면 공개 저장소여야 해요. 공개돼도 비밀번호와 연락처는 Secrets에 들어가서 남에게 보이지 않아요.

### 2. 아티스트 고르기
`config.yaml`의 `artists`를 원하는 가수로 바꾸세요.

- `kopis_keywords`: 국내 공연 제목에 들어가는 표기. 한글과 영문을 함께 적으면 놓치는 일이 줄어요.
- `ticketmaster_keyword`: Ticketmaster의 아티스트 이름과 똑같이 적어야 해요(대소문자, 띄어쓰기는 무시).
- `exclude_keywords`: 트리뷰트, 커버 공연처럼 이름은 같지만 원하지 않는 공연을 빼요.
- `news_queries`: 공식 사이트가 없거나 읽을 수 없는 아티스트는 뉴스 검색어를 넣으세요. Google 뉴스에서 공연 발표 기사(예매·티켓·투어·라인업 등)만 골라 알려요. 공연 후기 기사는 빼요.

**웹페이지에서 가수 추가:** 페이지의 "가수 추가" 칸에 이름만 넣으면 돼요. 몇 분 안에 KOPIS·Ticketmaster·멜론티켓·인터파크·예스24·뉴스 검색에 바로 붙이고, 지난 2~3주치 예매처 공지도 거슬러 찾아요. `OPENAI_API_KEY`가 있으면 한글/영문 표기(예: 혁오 ↔ HYUKOH)도 찾아 검색어에 넣어요. 추가한 가수는 `data/artists.json`에 저장돼요(공식 사이트·인스타그램은 `config.yaml`에 직접 넣어야 해요).

### 3. 공연 정보 API 키 받기 (무료)
| 이름 | 받는 곳 | Secret 이름 |
|---|---|---|
| KOPIS (국내) | kopis.or.kr → 오픈API → 서비스키 신청 | `KOPIS_API_KEY` |
| Ticketmaster (해외) | developer.ticketmaster.com → 가입 후 My Apps의 Consumer Key | `TICKETMASTER_API_KEY` |

저장소의 **Settings → Secrets and variables → Actions → New repository secret** 에 넣으세요. 둘 중 하나만 넣어도 동작해요.

### 4. 알림 채널 연결
쓰고 싶은 것만 설정하고, `config.yaml`의 `notify`에서 켜거나 끄세요.

**휴대폰 푸시 (ntfy, 무료)**
1. 휴대폰에 ntfy 앱을 설치하세요(App Store, Google Play).
2. 앱에서 + 를 눌러 남이 짐작하기 어려운 토픽 이름을 구독하세요. 예: `concert-a8f3k2q9`
3. 같은 이름을 Secret `NTFY_TOPIC`에 넣으세요. 토픽 이름을 아는 사람은 누구나 알림을 볼 수 있으니 길고 무작위로 정하세요.

**이메일 (Gmail 기준)**
1. Google 계정에서 2단계 인증을 켜고 "앱 비밀번호"를 만드세요.
2. Secrets: `SMTP_USER`(내 Gmail 주소), `SMTP_PASSWORD`(앱 비밀번호), `NOTIFY_EMAIL_TO`(받을 주소, 여러 개면 쉼표로 구분)
3. Gmail이 아니면 `SMTP_HOST`, `SMTP_PORT`도 넣으세요.

**문자 (한국 번호: Solapi)**
1. solapi.com 가입 → 발신번호 등록(본인 인증 필요) → API Key 발급.
2. Secrets: `SOLAPI_API_KEY`, `SOLAPI_API_SECRET`, `SMS_FROM`(등록한 발신번호), `NOTIFY_SMS_TO`(받을 번호, 쉼표로 여러 개)
3. `config.yaml`에서 `sms: true`. 문자는 건당 요금이 나가요. 긴 문자는 LMS로 보내져요.

해외 번호로 받으려면 `sms_provider: twilio`로 바꾸고 `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `SMS_FROM`(Twilio 번호)을 넣으세요.

### 5. 공식 인스타그램 연결 (선택, 설정이 가장 복잡해요)
인스타그램 화면을 긁어오는 방식은 로그인 요구와 차단 때문에 자동 실행에서 금방 막히고 약관에도 어긋나서, Meta의 공식 Instagram Graph API를 써요. 남의 공개 계정(비즈니스·크리에이터 계정)의 최근 게시물을 읽을 수 있고, 무료지만 내 계정 쪽 준비가 필요해요.

1. 내 인스타그램 계정을 **프로페셔널 계정**(크리에이터 또는 비즈니스)으로 전환하세요. 인스타그램 설정에서 무료로 할 수 있고, 새로 만든 빈 계정이어도 돼요.
2. 페이스북 페이지를 하나 만들고 그 인스타그램 계정을 연결하세요.
3. developers.facebook.com에서 앱을 만들고(유형: 비즈니스), "Facebook 로그인을 통한 Instagram API"를 추가하세요. 내가 쓸 용도라면 앱 검수 없이 개발 모드로 충분해요.
4. Graph API 탐색기에서 권한 `instagram_basic`, `pages_show_list`, `pages_read_engagement`, `business_management`를 골라 토큰을 만들고, 장기 토큰으로 바꾸세요.
5. 탐색기에서 `me/accounts`로 페이지 ID를 찾고, `{페이지ID}?fields=instagram_business_account`로 나오는 숫자를 확인하세요.
6. Secrets: `IG_USER_ID`(5번의 숫자), `IG_ACCESS_TOKEN`(장기 토큰)

장기 토큰은 보통 60일 뒤에 만료돼요. 만료되면 웹페이지 상단과 Actions 로그에 인스타그램 확인 실패가 뜨니, 그때 토큰을 새로 만들어 Secret을 바꿔주세요. Meta가 API 버전을 바꾸면 `IG_GRAPH_VERSION` Secret으로 버전(예: `v23.0`)을 지정할 수 있어요.

인스타그램을 연결하지 않아도 공식 웹사이트 감시와 공연 일정 API는 그대로 동작해요.

### 6. 예매 오픈 일시 자동 찾기 (OpenAI API, 선택이지만 권장)
새 공식 소식이 올라오면 OpenAI 모델이 글을 읽고 팬클럽 선예매, 선예매, 일반 예매 시각을 뽑아요. "Tickets on sale this Friday 10am local time" 같은 영어 공지나 "이번 주 금요일" 같은 표현도 알아들어요.

1. platform.openai.com에 가입하고 결제 수단(크레딧)을 등록한 뒤 API keys에서 키를 만드세요.
2. Secret `OPENAI_API_KEY`에 넣으세요.

새 공식 소식이 있을 때만 짧은 글 하나를 읽으므로 비용은 아주 적어요. 키가 없으면 "11월 20일(금) 오후 8시", "2026.11.20 20:00"처럼 한국어·숫자로 적힌 시간만 찾을 수 있어요. 사용할 모델은 `config.yaml`의 `open_time.model`에서 바꿀 수 있어요.

### 7. 웹페이지 켜기
**Settings → Pages** 에서 Source를 "Deploy from a branch", 브랜치는 `main`, 폴더는 `/docs`로 저장하세요.
주소(`https://내아이디.github.io/저장소이름/`)를 `config.yaml`의 `site.url`에 넣으면 알림에 링크가 같이 가요.

### 8. 예매 계획 저장
**자동 리마인더:** 멜론티켓·KOPIS·Ticketmaster에서 예매 오픈 시각이 나온 국내 공연은 버튼을 누르지 않아도 예매 계획에 자동으로 들어가고, 하루 전과 10분 전에 알림이 와요. 끄거나 나라를 바꾸려면 `config.yaml`의 `reminders`를 고치세요.

**웹페이지에서 바꾸기(로그인·비밀문구 없음):** "예매할게요"·"오픈 일시 수정"을 누르고 저장하거나 "예매 안 할래요"를 두 번 누르면 ntfy를 거쳐 전달되고, **5분마다 도는 확인에서 몇 분 안에** 반영돼요. "예매 안 할래요"로 취소한 공연은 자동 리마인더가 다시 넣지 않아요.

웹페이지와 저장소가 공개라서, 페이지 코드를 본 사람은 누구나 내 예매 계획을 바꿀 수 있어요. 막고 싶으면 `config.yaml`의 `site.edit_passphrase`를 `true`로 바꾸고 Secret `PICK_PASSPHRASE`에 비밀문구를 넣으세요. 그러면 기기마다 처음 한 번 비밀문구를 넣어야 저장돼요.

### 9. 점검하고 시작하기
1. **Actions** 탭 → concert-watch → Run workflow → "예시 공연으로 알림만 점검하기"를 체크하고 실행. 켜둔 채널로 예시 알림이 오면 연결 성공이에요.
2. 체크를 끄고 한 번 더 실행하면 첫 확인이 돌고 웹페이지가 생겨요. 이후로는 매시간 자동으로 돌아요.
3. 첫 실행 로그에서 공식 사이트마다 "내용 N줄을 기준으로 저장했어요"가 나오는지 보세요. "읽을 글자가 거의 없어요"가 나오는 사이트는 화면을 자바스크립트로 그려서 이 방식으로는 읽을 수 없는 곳이에요. 그 주소는 `official_pages`에서 빼거나 다른 공식 페이지(뉴스, 투어 페이지 등)로 바꿔주세요.

## 예매 오픈 일시는 이렇게 찾아요

"예매할게요"를 누르면 기본으로 **공식 발표에서 자동으로 찾기**가 선택돼요. 찾은 시간이 있으면 어디서 찾았는지와 함께 보여주고, 아직 없으면 발표될 때까지 기다렸다가 자동으로 넣어요. 고른 뒤에 시간이 새로 잡히면 "예매 오픈 일시를 찾았어요" 알림이 한 번 와요.

| 공연 | 쓰는 시간 |
|---|---|
| Ticketmaster 공연 | Ticketmaster의 선예매·일반 예매 시각 + 공식 소식에서 찾은 시각 |
| 국내(KOPIS) 공연 | 같은 아티스트의 공식 소식에서 찾은 시각 중 나라가 맞고 공연 날짜보다 앞선 것 |
| 공식 소식 자체 | 그 글에서 찾은 시각 |

선예매와 일반 예매가 모두 발표되면 각각 하루 전과 10분 전에 알려줘요. 원하는 시간이 따로 있으면 **직접 입력**을 고르면 되고, 그때는 그 시간만 써요.

**꼭 알아두세요.** 공지를 자동으로 읽는 것이라 틀릴 수 있어요. 특히 한 아티스트가 같은 나라에서 공연을 여러 번 발표하면 다른 공연의 예매 시간이 붙을 수 있고, 나라가 적혀 있지 않은 발표는 그 아티스트의 모든 공연에 붙어요. 중요한 예매라면 "내 예매 계획"에 보이는 시간과 출처를 한 번 확인하고, 다르면 직접 입력으로 바꿔주세요.

## 예매 리마인더는 이렇게 와요

| 알림 | 휴대폰 푸시(ntfy) | 이메일·문자 |
|---|---|---|
| 하루 전 | 정확한 시각 | 늦어도 1시간 안쪽 |
| 10분 전 | 정확한 시각 | 보내지 않음 |

GitHub Actions의 예약 실행은 수십 분 늦어질 수 있어서 정확한 시각을 맞출 수 없어요. 그래서 휴대폰 푸시는 알릴 시각 3시간 전쯤 ntfy 서버에 "이 시각에 보내줘"라고 맡겨 두고, ntfy가 정확한 시각에 보내요. 이메일과 문자는 그렇게 맡길 수가 없어서 하루 전 알림에만 써요. **10분 전 알림을 받으려면 휴대폰 푸시를 꼭 켜두세요.** 10분 전 푸시는 가장 높은 중요도로 와서 방해 금지 모드에서도 울리도록 ntfy 앱에서 설정할 수 있어요.

- 오픈까지 하루가 안 남았을 때 고르면, 하루 전 알림 대신 "N시간 뒤 열려요" 알림이 바로 와요.
- 오픈 일시를 바꾸면 새 시간 기준으로 다시 알려줘요. 다만 이미 ntfy에 맡겨진 알림(24시간 안쪽)은 취소할 수 없어서, 그 직전에 취소하거나 시간을 바꾸면 예전 알림이 한 번 더 올 수 있어요.

## 내 컴퓨터에서 돌려보기

```bash
pip install -r requirements.txt
export KOPIS_API_KEY=...            # 필요한 값만
python watch.py --dry-run           # 알림 없이 미리보기
python watch.py --reminders-only    # 예매 리마인더만 처리
python -m pytest -q                 # 테스트
```

## 알아두면 좋은 점

- **Claude 앱 푸시는 지원되지 않아요.** 외부 프로그램이 Claude 앱으로 알림을 보내는 방법이 없어서 ntfy 푸시로 대신했어요.
- **공식 사이트 감시는 "새로 생긴 줄"을 봐요.** 날짜나 공연 관련 단어가 있는 줄만 알리지만, 사이트 개편이나 굿즈 공지에도 가끔 알림이 갈 수 있어요. 반대로 투어 날짜를 이미지로만 올리는 사이트는 감지하지 못해요.
- **인스타그램은 글 내용으로 판단해요.** 캡션에 공연 관련 단어가 없는 포스터 이미지만 올라오면 놓칠 수 있어요. 단어는 `config.yaml`의 `official.keywords`에서 바꿀 수 있어요.
- **국내 공연은 KOPIS 등록 시점에 알려줘요.** 기획사 공지나 예매 오픈 직후 KOPIS에 등록되는 경우가 많아서, 팬카페나 공식 SNS 공지보다 늦을 수 있어요.
- **"오아시스"는 다른 공연 제목에도 흔해요.** 엉뚱한 공연이 잡히면 Oasis의 `kopis_keywords`에서 "오아시스"를 빼거나 `exclude_keywords`에 그 공연 제목의 단어를 넣으세요.
- **제목으로 찾기 때문에** 아티스트 이름이 제목에 없는 페스티벌 출연은 놓칠 수 있고, 비슷한 이름의 다른 공연이 잡힐 수 있어요. 그럴 땐 `kopis_keywords`와 `exclude_keywords`를 다듬으세요.
- **Ticketmaster는 북미·유럽·호주 위주**예요. 일본, 동남아 공연은 거의 잡히지 않아요.
- 매시간 확인 결과가 저장소에 커밋돼요. 커밋 기록이 많아지는 건 정상이에요.
- GitHub의 예약 실행은 몰리는 시간에 수십 분 늦어질 수 있어요. 저장소에 60일 동안 활동이 없으면 GitHub이 예약 실행을 멈추기도 하니, 그럴 땐 Actions 탭에서 다시 켜세요.
- KOPIS 조회는 31일 단위로 나눠 보내요. 아티스트가 아주 많으면 `lookahead_days`를 줄이거나 실행 간격을 늘리세요.
